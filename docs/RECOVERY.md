## Восстановление и устранение проблем

Руководство для **MIFA VPN Basic 1.1.x**. Команды выполняются на VPS с правами `root` или через `sudo`.

**Перед восстановлением:** сохраните конфигурацию, журнал незавершённой установки и резервные копии. Не удаляйте файлы и не запускайте повторный откат вслепую. Basic предназначен только для серверов, где Xray установлен самим Basic.

## Основные файлы

| Путь | Назначение |
|---|---|
| `/usr/local/etc/xray/config.json` | Конфигурация Xray с закрытым ключом |
| `/var/lib/mifa-vpn-basic/client.txt` | Ссылка `vless://` и параметры клиента |
| `/var/lib/mifa-vpn-basic/manifest` | Перечень файлов установки |
| `/var/lib/mifa-vpn-basic/journal.inprogress` | Журнал прерванной установки |
| `/var/backups/mifa-vpn-basic/` | Резервные копии |

## Установка завершилась ошибкой или прервалась

При обычной ошибке установщик пытается автоматически отменить выполненные изменения. Если после обрыва SSH, перезагрузки или аварийного завершения сохранился `journal.inprogress`, возможен ручной запуск отката:

```bash
sudo bash install.sh --rollback
```

**Перед запуском** убедитесь, что работаете с той же установкой Basic, сохраните журнал и backup и разберите предыдущие предупреждения. Повторять команду после частично неуспешного отката без выяснения причины нельзя.

Если откат завершился с **кодом 3**, состояние неоднозначно: журнал и резервные копии сохраняются, а потенциально чужие файлы и службы не должны удаляться автоматически. Проверьте сообщения `[WARN]`, сохраните данные и устраняйте конфликт вручную. **Не редактируйте журнал для принудительного продолжения.**

Basic проверяет принадлежность объектов установке и пытается остановить свою службу до файлового отката. Однако восстановление после потери питания и полная защита от параллельных изменений с правами root не гарантируются.

Чтобы уменьшить риск прерывания установки, используйте `tmux` или `screen`.

## Xray не запускается

| Что проверить | Команда |
|---|---|
| Состояние сервиса | `sudo systemctl status xray --no-pager` |
| Последние ошибки | `sudo journalctl -u xray -n 100 --no-pager` |
| Проверка конфигурации | `sudo -u xray /usr/local/bin/xray run -test -config /usr/local/etc/xray/config.json` |
| Прослушивание порта 443 | `sudo ss -tlnp 'sport = :443'` |

В последней команде подставьте ваш порт, если используется не `443`. Исправляйте конфигурацию только после сохранения её копии. При ошибке конфигурации Xray может не запуститься.

## Клиент не подключается

1. Проверьте, что Xray запущен и слушает нужный порт.
2. Убедитесь, что TCP-порт открыт в `ufw` и панели VPS-провайдера.
3. Проверьте IP-адрес, порт и SNI в ссылке `vless://`.
4. Убедитесь, что на клиентском устройстве правильно установлено время.
5. Проверьте соединение с другого устройства или через другую сеть.

Повторно показать данные подключения:

```bash
sudo cat /var/lib/mifa-vpn-basic/client.txt
```

Если вместо адреса сервера в ссылке указан `YOUR_SERVER_IP`, укажите реальный внешний IP. Не публикуйте ссылку: она содержит секреты доступа.

## Переустановка с новыми ключами

Для **успешно установленного** Basic сначала выполните штатное удаление, затем установку заново:

```bash
sudo bash uninstall.sh
sudo bash install.sh --sni DOMAIN --port PORT
```

Замените `DOMAIN` и `PORT` на свои значения. Старые клиентские ссылки перестанут работать. `uninstall.sh` сохраняет резервную копию прежней конфигурации в `/var/backups/mifa-vpn-basic/`.

## Восстановление прежних ключей и ссылки

Если Basic был штатно удалён, но нужно вернуть старую ссылку, используйте резервную копию, созданную `uninstall.sh`.

1. Найдите каталог резервной копии, путь к которому был показан при удалении. Проверьте в его `client.txt` прежние **SNI и порт**.
2. Установите Basic заново с **теми же SNI и портом**.
3. Остановите Xray и восстановите сохранённые конфигурацию и файл клиента. Подставьте реальный путь к копии вместо `BACKUP_DIR`:

```bash
sudo systemctl stop xray
BK=/var/backups/mifa-vpn-basic/BACKUP_DIR
sudo install -m 0640 -o root -g xray "$BK/usr/local/etc/xray/config.json" /usr/local/etc/xray/config.json
sudo install -m 0600 -o root -g root "$BK/var/lib/mifa-vpn-basic/client.txt" /var/lib/mifa-vpn-basic/client.txt
```

4. Проверьте конфигурацию и запустите сервис:

```bash
sudo -u xray /usr/local/bin/xray run -test -config /usr/local/etc/xray/config.json
sudo systemctl start xray
```

Проверьте восстановленное подключение. Новые ключи, созданные при переустановке, больше не используются.

## Ручная очистка после неудачного отката

**Только для опытного администратора и только после проверки принадлежности файлов Basic.** Эти команды необратимо удаляют объекты. Не используйте их для Xray, установленного сторонними пакетами, скриптами или панелями.

Сначала проверьте `/var/lib/mifa-vpn-basic/manifest`, сохраните конфигурацию и убедитесь, что `xray.service`, бинарник и пользователь `xray` были созданы именно Basic. Не удаляйте чужие файлы или службу при сомнениях.

Если принадлежность подтверждена, а штатные `uninstall.sh` и `--rollback` не могут завершить очистку:

```bash
sudo cp -a /usr/local/etc/xray /root/xray-config-backup
sudo systemctl disable --now xray
sudo rm -f /etc/systemd/system/xray.service /usr/local/bin/xray
sudo rm -rf /usr/local/etc/xray /var/lib/mifa-vpn-basic
sudo systemctl daemon-reload
```

Команда `sudo userdel xray` допустима **только если** Basic создал этого пользователя (`user_created=1` в манифесте). Сохраните содержимое манифеста **до** удаления служебного каталога.

## Старые установки Basic (до 1.1)

Для старых установок без манифеста предусмотрен отдельный режим удаления с резервным копированием:

```bash
sudo bash uninstall.sh --force
```

Если Xray установлен через APT, удаляйте его средствами пакетного менеджера; `uninstall.sh` может предложить `sudo apt-get purge xray`. Старые логи в `/var/log/xray` автоматически не удаляются.
