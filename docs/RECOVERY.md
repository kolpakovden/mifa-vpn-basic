# Восстановление и устранение проблем

Инструкции относятся к установке, созданной `install.sh` этой версии Basic.
Команды выполняются на сервере от root или через `sudo`. Для процедур 1, 2, 4 и 5
написаны сценарии в `tests/e2e_systemd.sh`; наличие тестов не означает, что они прошли.

**Статус экспериментальной ветки `experiment/deepseek-rollback`:** первый baseline
на Ubuntu 24.04 подтвердил четыре дефекта. Подготовлено исправление P1-4
(restore/staging), но его Linux-регрессии на Ubuntu 22.04/24.04/26.04 ещё не выполнены.
Остаются P1-2 (повторное удаление), P1-3 (симлинки остальных операций),
P1-5 (остановка службы), а также ограничения TOCTOU и проверки долговечности
после потери питания. Эта версия не объявляется готовой к релизу.
Перед восстановлением сохраните отдельные копии данных, журнала и backup;
не повторяйте rollback вслепую после частичного сбоя.

Пути Basic:

| Путь | Назначение |
|------|------------|
| `/usr/local/bin/xray` | бинарник Xray |
| `/usr/local/etc/xray/config.json` | конфиг сервера, содержит закрытый ключ |
| `/etc/systemd/system/xray.service` | unit systemd |
| `/var/lib/mifa-vpn-basic/client.txt` | данные клиента и ссылка `vless://` |
| `/var/lib/mifa-vpn-basic/manifest` | список файлов установки |
| `/var/lib/mifa-vpn-basic/journal.inprogress` | журнал незавершённой установки |
| `/var/backups/mifa-vpn-basic/` | резервные копии |

## 1. Установка завершилась ошибкой

Установщик пытается откатить изменения и, если его проверки не обнаружили ошибок, пишет:

```
[OK] Откат завершён: изменения установщика отменены
```

и завершается с исходным кодом ошибки установки. В текущей экспериментальной
версии это сообщение само по себе не доказывает полноту и безопасность отката.
Перед повторной установкой проверьте данные и состояние службы.

Если откатить всё не удалось, выводится

```
[WARN] Откат завершён не полностью: журнал /var/lib/mifa-vpn-basic/journal.inprogress и резервные копии в /var/backups/mifa-vpn-basic сохранены
```

а установщик завершается с кодом **3**. Текущий алгоритм сохраняет журнал при
обнаруженной ошибке; сохранность всех данных и backup ещё требует проверки.
Записанные действия `stop`/`disable` обрабатываются до файловых операций.
Однако после прерывания между `enable` и записью `stop` остановка службы может
быть пропущена. Безусловная остановка до любых файловых изменений пока не гарантируется.

Причина видна по сообщениям `[WARN]` выше: посторонний файл в каталоге,
который откат не может удалить, сервис, который не удалось остановить или
отключить, и т. п. Для нового журнала v2 запись `restoring` должна быть
записана и синхронизирована до замены файла. `restored` записывается после
сравнения содержимого, типа и метаданных с backup. Повтор при `restoring`
разрешает только проверку: при несовпадении возвращается код 3 без перезаписи.
Другие действия всё ещё могут повторно затронуть объекты после сбоя.
Команда повторного отката приведена для диагностики; сначала оцените журнал
и конфликты, сохраните данные и при необходимости выберите ручное восстановление:

```bash
sudo bash install.sh --rollback
```

При повреждённом журнале повторный откат не гарантирует восстановления: тогда
нужна ручная очистка (раздел 6).

Пакет `unzip`, установленный через `apt-get`, алгоритм отката не удаляет.

## 2. Установка прервана: обрыв SSH, перезагрузка, kill

Признак: preflight сообщает

```
[FAIL] найден журнал незавершённой установки /var/lib/mifa-vpn-basic/journal.inprogress
```

Откат по журналу:

```bash
sudo bash install.sh --rollback
```

Повторную установку рассматривайте после проверки результата восстановления.
`--rollback` обрабатывает записи остановки/отключения `xray.service`, удаления
файлов и пользователя `xray`, восстановления из `/var/backups/mifa-vpn-basic`.
Разрешённое имя пути в журнале ещё не подтверждает принадлежность текущего
объекта транзакции и не исключает выход через симлинки.

Перед выполнением действий текущий код проверяет записи журнала по allowlist.
Если эта проверка отклоняет запись, откат прерывается **до изменений
системы**, журнал и резервные копии сохраняются, а установщик завершается
с кодом **3**. Повторный `--rollback` возможен после устранения причины
(например, после исправления журнала); при повреждённых данных повторный
откат не гарантирует восстановления и может потребовать ручной очистки
(раздел 6). Проверка allowlist не является полной валидацией журнала,
идемпотентности или защитой от TOCTOU.

### Журналы v2 и совместимость restore

Новый журнал имеет точную первую строку `# MIFA VPN Basic journal v2`.
Порядок `restore → restoring → restored` и соответствие destination/backup
проверяются до действий. Неизвестная версия, повреждённая или обрезанная запись
означает отказ с кодом 3. Журналы без заголовка остаются v1: незавершённый
v1 restore отклоняется, даже если файл сейчас совпадает с backup. Не добавляйте
заголовок v2 вручную: это не устраняет неоднозначность старого журнала.

Restore сейчас поддерживает только обычные файлы, требует `python3` для
независимой проверки (байты, права, UID/GID, mtime с наносекундами, xattrs/ACL).
Недоступность проверки означает отказ. Симлинки, каталоги и недоверенные
родительские пути отклоняются. Существующий `*.mifa-restore` не используется.
Создаётся приватный каталог с уникальным именем рядом с destination;
после ошибки/прерывания он сохраняется для ручного разбора. Не удаляйте
обнаруженные staging-каталоги вслепую: процесс мог сохранить в них данные.

Проверки путей и закреплённый рабочий каталог не устраняют все гонки с другим
привилегированным процессом. Полная атомарность и восстановление после потери
питания не подтверждены. Не выполняйте конкурентные изменения путей установки.

Чтобы не попадать в эту ситуацию, запускайте установку в `tmux` или `screen`.

## 3. Сервис не запускается или падает

Состояние и журнал:

```bash
sudo systemctl status xray --no-pager
```

```bash
sudo journalctl -u xray -n 100 --no-pager
```

Проверка конфига от имени пользователя сервиса:

```bash
sudo -u xray /usr/local/bin/xray run -test -config /usr/local/etc/xray/config.json
```

Кто занимает порт (замените 443 на свой):

```bash
sudo ss -tlnp 'sport = :443'
```

Код выхода 23 означает ошибку конфига: systemd не перезапускает сервис, пока
конфиг не исправлен.

## 4. Вернуть прежние ключи и ссылку

Сценарий: Basic удалён `uninstall.sh` или переустановлен, а клиенты должны
продолжить работать с прежней ссылкой. `uninstall.sh` перед удалением сохраняет
конфиг и данные клиента и печатает каталог резервной копии:

```
Резервная копия конфига и данных клиента: /var/backups/mifa-vpn-basic/uninstall-20261121T120000Z
```

1. Установите Basic заново с **тем же портом и SNI**, что и в резервной копии
   (их можно посмотреть в `client.txt` копии):

   ```bash
   sudo cat /var/backups/mifa-vpn-basic/uninstall-20261121T120000Z/var/lib/mifa-vpn-basic/client.txt
   ```

   ```bash
   sudo bash install.sh --sni DOMAIN --port PORT
   ```

2. Остановите сервис:

   ```bash
   sudo systemctl stop xray
   ```

3. Верните конфиг и данные клиента из копии (подставьте свой каталог):

   ```bash
   BK=/var/backups/mifa-vpn-basic/uninstall-20261121T120000Z
   ```

   ```bash
   sudo install -m 0640 -o root -g xray "$BK/usr/local/etc/xray/config.json" /usr/local/etc/xray/config.json
   ```

   ```bash
   sudo install -m 0600 -o root -g root "$BK/var/lib/mifa-vpn-basic/client.txt" /var/lib/mifa-vpn-basic/client.txt
   ```

4. Проверьте конфиг и запустите сервис:

   ```bash
   sudo -u xray /usr/local/bin/xray run -test -config /usr/local/etc/xray/config.json
   ```

   ```bash
   sudo systemctl start xray
   ```

Прежняя ссылка снова работает. Новые ключи, созданные на шаге 1, больше не нужны.

## 5. Переустановка с новыми ключами

```bash
sudo bash uninstall.sh
```

```bash
sudo bash install.sh --sni DOMAIN --port PORT
```

Старые ссылки клиентов перестают работать. Резервная копия прежнего конфига
остаётся в `/var/backups/mifa-vpn-basic/`.

## 6. Ручная очистка

Нужна, только если `uninstall.sh` или `--rollback` завершились с предупреждениями
или с кодом 3, а также если журнал повреждён и автоматический откат невозможен.

Внимание: команды ниже удаляют файлы без возможности отмены. Перед удалением
убедитесь, что резервные копии в `/var/backups/mifa-vpn-basic` содержат нужные
файлы, и что удаляемые файлы, unit `xray.service` и пользователь `xray`
действительно созданы установкой Basic (сверьтесь с манифестом
`/var/lib/mifa-vpn-basic/manifest`). При необходимости сделайте дополнительную
копию конфига.

Если Xray установлен сторонним скриптом или пакетным менеджером (не этим
установщиком Basic), не выполняйте команды ручной очистки ниже — они рассчитаны
только на файлы Basic. Удаляйте стороннюю установку штатным способом,
предусмотренным её установщиком или пакетным менеджером. Для старых версий
MIFA Basic без манифеста порядок описан в разделе 8.

Сначала сохраните конфиг, если он нужен:

```bash
sudo cp -a /usr/local/etc/xray /root/xray-config-backup
```

```bash
sudo systemctl disable --now xray
```

```bash
sudo rm -f /etc/systemd/system/xray.service /usr/local/bin/xray
```

```bash
sudo rm -rf /usr/local/etc/xray /var/lib/mifa-vpn-basic
```

```bash
sudo systemctl daemon-reload
```

```bash
sudo userdel xray
```

`userdel` нужен, только если пользователя `xray` создал Basic (`user_created=1`
в манифесте).

## 7. Клиент не подключается

Проверьте по порядку:

1. Сервис активен и слушает порт (раздел 3).
2. Порт открыт в панели провайдера и в `ufw` (`sudo ufw status`).
3. В ссылке правильный адрес сервера. Если вместо адреса стоит `YOUR_SERVER_IP`,
   внешний IP не определился: замените его вручную.
4. На устройстве клиента верное время.
5. Подключение проверяется с другого устройства и из другой сети.
6. Цель REALITY всё ещё проходит проверку:

   ```bash
   bash install.sh --preflight --sni DOMAIN --port PORT
   ```

   На установленном сервере preflight сообщит, что Basic уже установлен; строки
   про REALITY при этом проверяются как обычно.

## 8. Установки Basic до версии 1.1

Старые версии не создавали манифест и могли ставить Xray через сторонний APT
или официальный скрипт XTLS. Удаление с резервной копией:

```bash
sudo bash uninstall.sh --force
```

Если Xray установлен APT-пакетом, `uninstall.sh` откажется и предложит
`sudo apt-get purge xray`. Логи старых версий в `/var/log/xray` не удаляются.
