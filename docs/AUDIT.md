# Аудит установщика Basic (Issue #1)

Дата: 2026-11-21. Объект: `install.sh`, `uninstall.sh` и `.github/workflows/basic-checks.yml`
в ветке `hardening/fresh-host-safety` на коммите `188f9e6` (до переработки).

Аудит выполнен чтением кода, запуском `shellcheck`, `bash -n` и экспериментами с
настоящим бинарником Xray v26.11.9 и OpenSSL из Ubuntu 22.04, 24.04 и 26.04 в Docker.
Внешние VPS и действующие серверы MIFA не использовались.

## Критические проблемы

| # | Где | Проблема | Последствие |
|---|-----|----------|-------------|
| A1 | `install_xray` | Резервная установка через `bash -c "$(curl ... install-release.sh)"` без проверки целостности. | Исполнение непроверенного кода от root. |
| A2 | `install_xray` | Основной путь - сторонний APT-репозиторий `deb.xray.guru`; ключ скачивается без сверки отпечатка. | Владелец стороннего репозитория получает возможность ставить пакеты от root при каждом `apt upgrade`. |
| A3 | разбор `xray x25519` | Xray v26.11.9 печатает `Password (PublicKey): ...`. Скрипт ищет только `^Password:` и `^Public key:`. | На свежем VPS с текущим Xray установка падает после установки бинарника и оставляет систему в промежуточном состоянии. Проверено на реальном бинарнике. |
| A4 | запись конфига | `cat > /usr/local/etc/xray/config.json` пишет сразу в рабочий путь, без staging, резервной копии и rollback. `xray run -test` вызывается уже после перезаписи. | Ошибка на любом шаге оставляет полуустановленную систему. |
| A5 | SNI/target | Молча используется `www.microsoft.com`; сетевая проверка цели не выполняется. Target может указывать на `127.0.0.1` или внутреннюю сеть. | Неработающий REALITY или проброс неаутентифицированного трафика из интернета на внутренний сервис. |
| A6 | конфиг Xray | Нет запрета на исходящие соединения клиентов к `127.0.0.0/8`, `169.254.0.0/16` и частным сетям. | Зависит от версии Xray: в v26.11.9 `freedom` блокирует такие адреса для VLESS по умолчанию (встроенные `finalRules`, проверено по исходникам и в e2e). С более старыми версиями из стороннего APT владелец ссылки мог обращаться к локальным сервисам VPS и metadata API облака. |

## Существенные проблемы

| # | Где | Проблема |
|---|-----|----------|
| B1 | `is_port_free` | Если нет ни `ss`, ни `netstat`, порт считается свободным. Проверяются TCP и UDP вместе, хотя Xray слушает только TCP. |
| B2 | `validate_port` | `08443` проходит регулярное выражение, но в `(( ))` трактуется как восьмеричное число и роняет скрипт. |
| B3 | `validate_sni` | Принимаются `..`, `-a.b`, `a..b` и другие некорректные имена. |
| B4 | права | Конфиг с приватным ключом получает владельца `nobody`/`nogroup` и режим 640, то есть читается группой `nogroup`. |
| B5 | логи | `access.log` и `error.log` в `/var/log/xray` без ротации: неограниченный рост на маленьком VPS и журнал посещений пользователей. |
| B6 | сеть | `curl https://api.ipify.org` без таймаута может зависнуть; результат не проверяется как IP-адрес. |
| B7 | VLESS URI | Нет `encryption=none`; IPv6-адрес сервера не заключается в скобки. |
| B8 | аргументы | `--port` без значения приводит к `shift` за пределы списка и тихому выходу из-за `set -e`. |
| B9 | интерактивный режим | Без TTY `read` получает EOF и скрипт завершается без сообщения. |
| B10 | guard из PR #2 | Не учитывает unit-файлы `xray.service` и `xray@.service`, бинарник в `/usr/local/bin/xray` вне `PATH`, запущенный процесс `xray`, непустой `/usr/local/etc/xray`. |
| B11 | `uninstall.sh` | `rm -rf /usr/local/etc/xray` без резервной копии и без проверки, что Xray ставил именно Basic. |
| B12 | окружение | Нет проверок ОС, архитектуры, systemd как PID 1, свободного места, блокировки параллельного запуска. |
| B13 | firewall | Не проверяется `ufw` и не объясняется необходимость открыть порт у провайдера. |

## Тесты и CI до переработки

- Один job на `ubuntu-latest`: `bash -n`, `--help`, отказ на `--port 0`, отказ при подставном `xray` в `PATH`.
- Нет `shellcheck`, нет матрицы Ubuntu 22.04/24.04/26.04, нет тестов разбора ключей,
  REALITY-проверки, конфликта порта, повторной установки и rollback.
- `shellcheck -S style` на исходных скриптах замечаний не даёт.

## Что изменено

Подробности - в описании PR #2 и в `README.md`. Кратко:

- A1, A2: Xray скачивается только из официального релиза `XTLS/Xray-core` закреплённой версии,
  SHA256 закреплён в скрипте и сверяется перед распаковкой; дополнительно сверяется `.dgst` релиза.
- A3: разбор всех трёх известных форматов вывода и перекрёстная проверка `xray x25519 -i`.
- A4: конфиг собирается и проверяется `xray run -test` во временном каталоге, устанавливается атомарно;
  все изменения записываются в журнал, при ошибке выполняется автоматический откат,
  после аварийного прерывания доступен `install.sh --rollback`.
- A5: SNI задаётся явно; target проверяется: DNS, запрет частных адресов, TLS 1.3, X25519, HTTP/2,
  валидный сертификат для SNI.
- A6: в конфиг добавлено явное правило маршрутизации в `blackhole` для локальных и частных
  адресов - дополнительно к встроенной защите Xray v26 и на случай `--xray-version`.
- B1-B13: исправлены или вынесены в preflight с понятным сообщением.
